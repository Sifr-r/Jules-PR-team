# Palette niche — Visual system

1. **Intent:** Identify the reader or operator, triggering task, hierarchy they need to understand, and invariant that visual roles remain consistent and readable across the assigned surface. Inspect existing tokens, components, theme variants, and documented brand decisions; actual implementation and current human direction help resolve stale documentation.
2. **Questions:** Can users distinguish primary action, supporting information, navigation, data, and feedback without competing emphasis? Do typography, spacing, color, density, and component variants express meaningful roles rather than arbitrary variation? Does the system still work with long content, zoom, validation, and supported themes?
3. **Evidence:** Map the assigned surface's type roles, foreground/background pairs, spacing rhythm, alignment, and component states to their existing owners. Identify concrete drift or explain a requested new choice against the brief. Inspect actual font loading, wrapping, text measure, and content density when rendered evidence is available. Check applicable contrast requirements; brand preferences do not by themselves excuse unreadable text. A screenshot alone cannot establish exact contrast or assistive-technology support.
4. **Bounded action and proof:** Reuse established tokens and components. For fresh work or authorized system changes, define the smallest coherent set of role-based values and apply it consistently; avoid a new framework or mandatory typeface. Preserve explicit brand requirements and use emphasis where it communicates hierarchy. Verify representative states, relevant themes, normal and narrow layouts, and content extremes. Inspect the integrated result for CSS conflicts and unintentional changes to shared consumers; document unavailable render checks.
5. **Stop and handoff:** Stop when the assigned visual roles are consistent, readable, and supported by the recorded evidence. Hand systemic token migrations or cross-surface effects to the coordinator, semantic problems to the semantics niche, and resource costs such as font loading to Bolt. Do not turn a local refinement into an unrequested design-system replacement.
